# 3. SQL-запросы, представления и аналитика

Тексты запросов — в [services/core/sql/queries](../../services/core/sql/queries); они
встроены в приложение (`go:embed`) и выполняются эндпоинтами `/api/v1/reports/*`, а
также запускаются вручную через psql (`PREPARE q AS …; EXECUTE q(…)`).

## 3.1. Запросы

| № | Файл / эндпоинт | Задача предметной области | Конструкции |
|---|---|---|---|
| Q01 | `q01_barber_day_schedule.sql` · `/reports/day-schedule` | Расписание мастера на день с клиентами и услугами | JOIN 5 таблиц, LEFT JOIN, `string_agg`, GROUP BY |
| Q02 | `q02_client_history.sql` · `/reports/client-history` | История визитов клиента, интервал между визитами | CTE, коррелированный подзапрос, **LAG** |
| Q03 | `q03_revenue_by_branch_month.sql` · `/reports/revenue-by-branch` | Выручка филиалов по месяцам, динамика и доля в сети | многоэтапный CTE, **LAG**, **SUM() OVER (PARTITION BY)**, именованное окно |
| **Q04** | `q04_barber_ranking.sql` · `/reports/barber-ranking` | **Комплексный отчёт**: рейтинг мастеров — визиты, выручка, средний чек, неявки, рейтинг, загрузка смен, место в филиале | 6 этапов CTE, LEFT JOIN, агрегаты с FILTER, **AVG/RANK/DENSE_RANK OVER** |
| **Q05** | `q05_rfm_segmentation.sql` · `/reports/rfm` | **Комплексный отчёт**: RFM-сегментация клиентов | 3 этапа CTE, LATERAL, **NTILE**, CASE-правила сегментов, COUNT/AVG OVER |
| Q06 | `q06_top_services.sql` · `/reports/top-services` | Популярность услуг, доля в категории | JOIN 4 таблиц, GROUP BY + **HAVING**, `SUM(SUM()) OVER`, RANK |
| Q07 | `q07_churn_risk.sql` · `/reports/churn-risk` | Клиенты в зоне оттока и их «любимый» мастер | CTE, HAVING, **NOT EXISTS**, **ROW_NUMBER** |
| Q08 | `q08_no_show_offenders.sql` · `/reports/no-shows` | Систематические неявки, потерянная выручка | LATERAL, GROUP BY + **HAVING**, FILTER, **EXISTS** |
| Q09 | `q09_utilization_weekly.sql` · `/reports/utilization` | Загрузка мастеров по неделям | CTE, **LEFT JOIN по диапазону времени**, двухуровневая агрегация |
| Q10 | `q10_cohort_retention.sql` · `/reports/cohorts` | Когортное удержание клиентов | многоэтапный CTE, DISTINCT, **FIRST_VALUE** |
| Q11 | `q11_daily_revenue.sql` · `/reports/daily-revenue` | Выручка по дням: нарастающий итог, скользящее среднее | `generate_series` + LEFT JOIN, **SUM OVER (ORDER BY)**, **AVG OVER (ROWS 6 PRECEDING)** |
| — | функция `crm.free_slots` · `/barbers/{id}/free-slots` | Свободные слоты под набор услуг | CTE, `generate_series`, **NOT EXISTS / EXISTS** с оператором `&&` |

Каждая конструкция применяется там, где она решает задачу: оконные функции — для
ранжирования, динамики и нарастающих итогов, `NOT EXISTS` — для «нет будущей записи»
и свободных слотов, `HAVING` — для порогов (минимум продаж, минимум неявок).

### Комплексный отчёт Q04 «Рейтинг мастеров»

1. `period_appts` — записи периода;
2. `barber_stats` — визиты, неявки, отработанные минуты (агрегаты с `FILTER`);
3. `revenue` — выручка по зафиксированным ценам;
4. `ratings` — средняя оценка и число отзывов;
5. `shift_time` — суммарная длительность смен (знаменатель загрузки);
6. `scored` — сводка по мастеру: средний чек, доля неявок, загрузка;
7. итог — `RANK()` в филиале, `DENSE_RANK()` по рейтингу и отклонение выручки от
   средней по филиалу (`AVG() OVER (PARTITION BY branch_id)`).

### Комплексный отчёт Q05 «RFM-сегментация»

1. `base` — для каждого клиента за 365 дней: давность последнего визита (Recency),
   число визитов (Frequency), сумма (Monetary);
2. `scores` — баллы 1–5 квинтилями `NTILE(5)` по каждому показателю;
3. `segmented` — сегмент по правилам («Чемпионы», «Лояльные», «Новички», «Под угрозой
   ухода», «Потерянные», «Требуют внимания»); итог — размер и средний чек сегмента.

## 3.2. Представления

| Объект | Назначение |
|---|---|
| `crm.v_appointment_details` | Карточка записи: клиент, мастер, филиал смены, состав, сумма, оплачено, оценка. Используется списком и карточкой записей API |
| `crm.v_client_stats` | Производные атрибуты клиента (число визитов, неявок, последний и следующий визит) + бонусный счёт. В миграции 0010 переписано через `LATERAL` для производительности |
| `crm.mv_barber_monthly_kpi` | **Материализованное** представление: KPI мастера по месяцам (визиты, отмены, неявки, выручка, средний чек, загрузка смен, рейтинг) |

### Механизм обновления материализованного представления

* уникальный индекс `(barber_id, month)` позволяет `REFRESH MATERIALIZED VIEW
  CONCURRENTLY` — чтение отчёта не блокируется во время обновления;
* функция `crm.refresh_kpi()` (`SECURITY DEFINER`: обновлять MV может только владелец);
* вызов: фоновый планировщик сервиса (`CORE_KPI_REFRESH_INTERVAL`, по умолчанию 10 мин),
  эндпоинт `POST /api/v1/reports/kpi/refresh`, `make kpi-refresh`, конец seed;
* столбец `refreshed_at` показывает момент актуальности данных.
