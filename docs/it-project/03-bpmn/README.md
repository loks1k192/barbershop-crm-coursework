## Используемые элементы нотации

| Элемент | Где используется |
|---|---|
| Пул / дорожка | Пулы «Клиент» и «Сеть барбершопов»; дорожки «Администратор», «Барбер», «CRM-система» |
| Стартовое событие (простое, сообщения) | «Нужна стрижка»; «Запрос свободного времени» |
| Промежуточные события сообщения (ловящее/бросающее) | «Слоты отправлены», «Заявка получена», «Подтверждение получено», «Клиент пришёл» |
| Промежуточное событие таймера | «За 24 ч до визита», «Наступило время визита», «15 мин после начала» |
| Граничное событие ошибки, конечное событие ошибки | «Сбой БД» на задаче проверки строк → «Пакет откатан целиком» |
| Задачи: пользовательская, сервисная, отправки, получения, ручная | Действия персонала, вызовы функций БД, обмен сообщениями с клиентом, визит |
| Исключающий шлюз (XOR) | «Запись создана?», «Расчёт выполнен?», «Что требуется?» |
| Шлюз на основе событий | Клиент ждёт подтверждения **или** отказа; администратор ждёт прихода **или** истечения 15 минут |
| Параллельный шлюз (AND) | Одновременная запись ошибок строк и загрузка корректных строк |
| Поток по умолчанию (косая черта) | «нет отклонённых строк» |
| Поток сообщений (пунктир) | Взаимодействие клиента и сети |
| Хранилище данных + ассоциация | БД barbershop, `staging.client_import_rows`, `audit.audit_log` |

## 1. Запись клиента и обслуживание визита

Клиент выбирает мастера, услуги и дату и запрашивает свободное время; CRM
рассчитывает слоты (`crm.free_slots`). Клиент отправляет заявку; CRM создаёт запись
(`crm.book_appointment`). Если время уже занято (ограничение EXCLUDE, SQLSTATE 23P01)
или запись выходит за смену (CR003), клиент получает отказ с другими слотами и
выбирает время повторно — шлюз на основе событий в пуле клиента. После подтверждения
по таймеру за 24 ч отправляется напоминание. В день визита администратор ждёт
клиента: если через 15 минут после начала клиента нет — фиксируется неявка
(`no_show`), иначе визит начинается, барбер оказывает услуги, администратор
принимает оплату. CRM атомарно завершает визит (`crm.complete_appointment`): статус,
оплаты, списание и начисление бонусов, уровень лояльности. При превышении лимита
списания бонусов (CR009) транзакция откатывается и расчёт повторяется. Клиент
получает чек и сведения о начисленных бонусах.

## 2. Отмена и перенос записи

Пул клиента свёрнут («чёрный ящик»). Администратор находит запись; при переносе
согласует новое время по свободным слотам и вызывает `crm.reschedule_appointment`
(конфликт 23P01 возвращает к выбору времени). При отмене указывается обязательная
причина и вызывается `crm.cancel_appointment`; если визит уже начат или завершён
(CR002), отмена отклоняется. Изменение статуса автоматически попадает в историю
статусов и журнал аудита (триггеры), освободившееся время сразу доступно для записи.

## 3. Пакетная загрузка клиентской базы

Администратор готовит CSV из прежней системы и загружает его. CRM проверяет
структуру файла (ошибка — 400 и исправление файла), создаёт пакет и копирует строки
в `staging`, затем `staging.process_client_import` нормализует и проверяет каждую
строку; параллельно ошибки строк пишутся в `import_errors`, корректные строки
добавляются или обновляют клиентов (бонусные счета создаёт триггер). Сбой БД
(граничное событие ошибки) откатывает пакет целиком. По отчёту о загрузке
администратор разбирает отклонённые строки.
