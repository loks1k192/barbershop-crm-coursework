## Используемая нотация

* **Прямоугольник** — сильная сущность; **двойной прямоугольник** — слабая сущность
  (не идентифицируется без «владельца»).
* **Ромб** — связь; **двойной ромб** — идентифицирующая связь слабой сущности.
* **Овал** — атрибут; подчёркнутый — ключ; подчёркнутый пунктиром — частичный ключ
  слабой сущности; **пунктирный овал** — производный атрибут (вычисляется, не хранится);
  овал с дочерними овалами — составной атрибут.
* **Одинарная линия** — частичное участие, **двойная** — полное (обязательное).
* **1 / N / M** — кардинальность связи.

## Сущности

| Сущность | Тип | Смысл |
|---|---|---|
| ФИЛИАЛ | сильная | Барбершоп сети с часами работы |
| МАСТЕР | сильная | Барбер, закреплён за основным филиалом, имеет грейд |
| НАСТРОЙКИ ЗАПИСИ | слабая (1:1 от МАСТЕР) | Шаг сетки слотов, горизонт и мин. время онлайн-записи |
| СМЕНА | слабая (от МАСТЕР, частичный ключ — дата) | Рабочий интервал мастера в конкретный день в конкретном филиале |
| КАТЕГОРИЯ УСЛУГ | сильная | Стрижки, борода, уход, комплексы |
| УСЛУГА | сильная | Позиция общего каталога сети (базовая цена/длительность) |
| КЛИЕНТ | сильная | Идентифицируется телефоном; ФИО — составной атрибут |
| БОНУСНЫЙ СЧЁТ | слабая (1:1 от КЛИЕНТ) | Уровень лояльности, баланс бонусов, сумма покупок |
| ЗАПИСЬ (ВИЗИТ) | сильная | Запись клиента к мастеру на интервал времени со статусом |
| ОПЛАТА | сильная | Платёж по визиту (наличные/карта/онлайн/бонусы) |
| БОНУСНАЯ ОПЕРАЦИЯ | сильная | Начисление/списание/корректировка бонусов |
| ОТЗЫВ | слабая (1:1 от ЗАПИСЬ) | Оценка завершённого визита |
| ИЗМЕНЕНИЕ СТАТУСА | слабая (от ЗАПИСЬ, частичный ключ — момент) | История жизненного цикла записи |

## Связи и кардинальности

| Связь | Участники | Кардинальность | Участие |
|---|---|---|---|
| РАБОТАЕТ В | ФИЛИАЛ — МАСТЕР | 1:N | мастер — полное |
| ПРОВОДИТСЯ В | ФИЛИАЛ — СМЕНА | 1:N | смена — полное |
| ВЫХОДИТ НА (идент.) | МАСТЕР — СМЕНА | 1:N | смена — полное |
| ИМЕЕТ (идент.) | МАСТЕР — НАСТРОЙКИ | **1:1** | полное с обеих сторон |
| ОТНОСИТСЯ К | КАТЕГОРИЯ — УСЛУГА | 1:N | услуга — полное |
| ОКАЗЫВАЕТ | МАСТЕР — УСЛУГА | **M:N**, атрибуты связи: цена мастера, длительность, активна | частичное |
| ОБСЛУЖИВАЕТ | МАСТЕР — ЗАПИСЬ | 1:N | запись — полное |
| ОФОРМЛЯЕТ | КЛИЕНТ — ЗАПИСЬ | 1:N | запись — полное |
| ВКЛЮЧАЕТ | ЗАПИСЬ — УСЛУГА | **M:N**, атрибуты связи: цена и длительность на момент записи | запись — полное (≥ 1 услуги) |
| ОПЛАЧИВАЕТСЯ | ЗАПИСЬ — ОПЛАТА | 1:N | оплата — полное |
| ОЦЕНИВАЕТСЯ (идент.) | ЗАПИСЬ — ОТЗЫВ | **1:1** | отзыв — полное |
| ФИКСИРУЕТ (идент.) | ЗАПИСЬ — ИЗМЕНЕНИЕ СТАТУСА | 1:N | изменение — полное |
| ВЛАДЕЕТ (идент.) | КЛИЕНТ — БОНУСНЫЙ СЧЁТ | **1:1** | полное с обеих сторон |
| ДВИЖЕНИЕ | БОНУСНЫЙ СЧЁТ — БОНУСНАЯ ОПЕРАЦИЯ | 1:N | операция — полное |
| ОСНОВАНИЕ | ЗАПИСЬ — БОНУСНАЯ ОПЕРАЦИЯ | 1:N | частичное (корректировки без визита) |

## Производные атрибуты

«Стаж» мастера, «Длительность» смены, «Возраст», «Число визитов» и «Последний визит»
клиента, «Стоимость» записи не хранятся — они вычисляются (представления
`v_client_stats`, `v_appointment_details`). В исходном проекте `visits_count` и
`last_visit` хранились в таблице клиентов, что нарушало 3НФ; в курсовом проекте это
исправлено.

## Переход к реляционной модели

Каждая сущность → таблица; связи 1:N → внешний ключ на стороне N; связи 1:1 со слабой
сущностью → общий первичный ключ (`barber_settings.barber_id`, `loyalty_accounts.client_id`,
`reviews.appointment_id`); связи M:N → ассоциативные таблицы `barber_services` и
`appointment_services`, атрибуты связи становятся их столбцами. Физическая модель — в
[docs/db/02-data-model.md](../../db/02-data-model.md).
