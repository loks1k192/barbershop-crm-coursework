# Функциональная модель (IDEF0)

Функциональная модель CRM сети барбершопов выполнена в нотации **IDEF0**
(Р 50.1.028-2001): каждая функция — блок с названием-глаголом, стрелки по сторонам
блока обозначают **I**nput (вход, слева), **C**ontrol (управление, сверху),
**O**utput (выход, справа) и **M**echanism (механизм, снизу).

**Цель моделирования:** определить функции CRM-системы сети барбершопов и
информационные потоки между ними для проектирования БД и приложения.
**Точка зрения:** управляющий сетью барбершопов.

## A-0. Контекст

| Тип | Стрелки |
|---|---|
| Входы | Запросы клиентов на запись; сведения о филиалах, мастерах и услугах; клиентская база из прежних систем (CSV); оплата клиента |
| Управление | Регламенты сети (правила записи, отмены, оплаты); программа лояльности; законодательство (152-ФЗ, 54-ФЗ); прайс-листы и часы работы филиалов |
| Выходы | Подтверждения и напоминания; оказанные услуги; чеки; бонусные операции и уровень лояльности; аналитические отчёты и KPI; журнал аудита |
| Механизмы | Администраторы филиалов; барберы; управляющий сетью; CRM-система Barber CRM (REST API + PostgreSQL) |

## A0. Декомпозиция

| Блок | Функция | Ключевые входы → выходы | Реализация в системе |
|---|---|---|---|
| A1 | Вести справочники: филиалы, услуги, мастера, прайсы | Сведения о филиалах и персонале → каталог услуг и прайсы, мастера и филиалы | `/branches`, `/services`, `/categories`, `/barbers`, `/barbers/{id}/services` |
| A2 | Планировать график работы мастеров | Мастера и филиалы → график смен | `/shifts`, триггер `trg_work_shifts_validate` |
| A3 | Управлять клиентской базой и лояльностью | CSV, новые клиенты, бонусные операции → карточки клиентов, бонусные счета, отчёт о загрузке | `/clients`, `/import/clients`, `staging.process_client_import`, `loyalty_accounts` |
| A4 | Записывать клиентов на услуги | Запросы, карточки → подтверждения, записи, новые клиенты | `/barbers/{id}/free-slots`, `POST /appointments`, `crm.book_appointment` |
| A5 | Обслуживать клиентов и проводить расчёт | Записи, оплата, бонусные счета → оказанные услуги, чеки, бонусные операции, данные о визитах | `/appointments/{id}/status`, `/complete`, `/review`, `crm.complete_appointment` |
| A6 | Формировать аналитику и отчётность | График, клиентская база, визиты → отчёты и KPI, журнал аудита; управленческие решения (обратная связь в A1, A2) | `/reports/*`, `mv_barber_monthly_kpi`, `/audit` |

Обратные связи: «Новые клиенты» (A4 → A3) и «Бонусные операции, изменение уровня»
(A5 → A3) — по входу (проходят под блоками); «Управленческие решения» (A6 → A1, A2) —
по управлению (проходят над блоками).

ICOM-коды граничных стрелок A0: I1 запросы на запись, I2 сведения о филиалах и
персонале, I3 клиентская база CSV, I4 оплата; C1 регламенты, C2 программа
лояльности, C3 152-ФЗ, C4 требования к отчётности; O1 подтверждения, O2 оказанные
услуги, O3 чеки, O4 бонусные операции, O5 отчёты и KPI, O6 отчёт о загрузке,
O7 журнал аудита; M1 администратор, M2 барбер, M3 управляющий, M4 CRM-система.

## A4. Записывать клиентов на услуги

| Блок | Функция | Правила (управление) | Реализация |
|---|---|---|---|
| A41 | Подобрать свободное время | График смен, длительности из прайса, шаг сетки, минимальное время до записи, компактный режим | `crm.free_slots` |
| A42 | Идентифицировать или зарегистрировать клиента | Клиент определяется по телефону | `book_appointment`: `INSERT … ON CONFLICT (phone)` |
| A43 | Зарегистрировать запись | Окно онлайн-записи, непересечение (EXCLUDE), запись внутри смены, фиксация цен | `crm.book_appointment` |
| A44 | Сопровождать запись | Правила отмены (причина обязательна), переноса, допустимые переходы статусов | `cancel_appointment`, `reschedule_appointment`, `PATCH /status` |

Обратная связь «Освободившееся время» (A44 → A41): отменённые и перенесённые записи
не участвуют в EXCLUDE-ограничении, поэтому время сразу снова доступно для записи.

## A5. Обслуживать клиентов и проводить расчёт

| Блок | Функция | Правила | Реализация |
|---|---|---|---|
| A51 | Принять клиента и начать визит | Начало не ранее чем за 30 мин; неявка — только после начала | `PATCH /status` (`in_progress`, `no_show`) + триггер |
| A52 | Оказать услуги | Состав услуг и цены зафиксированы в записи | `appointment_services` |
| A53 | Рассчитать стоимость и принять оплату | Бонусами ≤ 30 % чека и ≤ баланса; Σ оплат ≤ стоимости | `crm.complete_appointment`, `trg_payments_validate` |
| A54 | Начислить и списать бонусы, пересчитать уровень | Ставки 3/5/7 %, пороги 15 000 / 50 000 ₽, уровень только повышается | `bonus_transactions`, `trg_bonus_tx_apply`, `trg_loyalty_level` |
| A55 | Получить отзыв о визите | Только завершённый визит, ≤ 30 дней, один отзыв | `POST /review`, `trg_reviews_validate` |

A53–A54 выполняются в одной транзакции: при отказе (например, превышен лимит
бонусов) ничего не записывается и визит возвращается на повторный расчёт
(обратная связь на A53).
